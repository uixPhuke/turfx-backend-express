Razorpay webhook: configure `https://<api-domain>/api/v2/payments/webhook` separately in test and live dashboards. Use independent signing secrets. Subscribe to captured/failed payment and processed/failed refund events supported by the handler; verify exact event names in payment.service before dashboard setup. Do not trust a browser success result without server verification. Record provider IDs rather than card/bank details in release evidence.

Android: add the correct Firebase Android app for each package (`com.uixphuke.playza.staging` and production identifier), provide GOOGLE_SERVICES_JSON as an EAS file variable, upload FCM HTTP v1 credentials through EAS credentials management. iOS: enable Push Notifications entitlement through EAS and provide an APNs key with correct Apple team/app access. Private service-account/APNs keys belong in EAS credential storage, never EXPO_PUBLIC variables. Test opt-in, denied permission, token rotation, logout and invalid token receipts.

Android Maps SDK key must restrict Android package and SHA-1 fingerprints for development/preview/store signing separately, and restrict API usage to Maps SDK for Android. Current native map uses Apple Maps on iOS, so no iOS Google key is required. No background location is required; do not add background permissions. No universal links are claimed: custom URL schemes exist, while associated domains require an owned domain and hosted verification files before enabling.
